**让日常药物警戒（PV）义务可执行、可追溯、可审计。**

一个面向中国药品上市许可持有人（MAH）、医疗机构与药物警戒部门的本地化合规工作台，覆盖八大领域：
**个例安全性报告（ICSR）、信号检测与评估（SIGNAL）、定期安全性报告（PSUR/PBRER）、风险管理（RMP）、
医学文献监测（LIT）、疫苗疑似预防接种异常反应（AEFI）、药品投诉与召回（COMPLAINT）、药物警戒体系质量合规（GVP）**。

把「文件规定应该怎么做」变成「系统推着你做、做错拦住、做完自动留痕」，并在检查前告诉你哪里有风险。

本产品由 **LeebertyGXP 架构改造而来**：合规内核（哈希链审计、双要素电子签名、职责分离）与「领域是数据」
的设计原封保留，领域集合整体替换为治疗性药物警戒。
**这不再是 GMP/GLP/GCP 工作台**——设备校准、批次放行与 GxP 生产领域已不在本产品的范畴内。

| 模块 | 能力 |

| **领域模块** | 八大领域各自的流程、检查表与岗位职责矩阵 |

## 设计核心

1. **PV 各领域的合规义务高度同构** —— 快速报告、信号评估、PSUR 编制、RMP 更新、文献筛查、偏差/CAPA，
   本质都是「一条受控的安全性记录 + 一串有角色与签名门槛的步骤」。所以**领域是数据，不是代码**：
   加一个新流程只需往 `seed/workflows/` 放一个 JSON 文件
2. **控制做进机制** —— 审计追踪用哈希链实现（只可追加，改库被触发器拦截）；电子签名强制两个独立识别要素；
   所有记录修改强制填写理由；数据问题的提出人不能自己关闭
3. **职责写在图上** —— 领域页第一屏就是工作流程图，每步下面直接列出负责岗位、签名门槛与操作指引
4. **检查就绪度常态可见** —— 法规条款变成可逐条判定的检查表，未关闭的严重缺陷、超期记录、
   文件审核欠账汇成一个带**具名阻碍项**的就绪度评分
5. **工作流自己跑** —— 后台监控进程定时扫描，不需要任何人打开页面

## 这个项目是什么，以及它不是什么

**如实说明**（原文见仓库 README 第九节）：

- **定位**：技术演示与参考实现，**不是经过验证的系统**——不可直接用于生产环境的法规申报
- **演示数据是虚构的**：用于展示流程，不能当作真实记录
- **内置账号共用密码是已标注的风险**（21 CFR Part 11.300(a) 要求账号唯一），正式使用前必须改造
- **评分与检查表不构成法规符合性的最终判定**

> ⚠️ **免责**：本项目为技术演示与学习参考，不构成法规咨询意见；实际药物警戒工作请以现行法规
> （GVP、ICH E2 系列、药品管理法等）及属地监管部门要求为准。
