**面向中国市场准入（market access）场景**，而不是照搬欧美 HTA 模板。

国内 HEOR / 市场准入岗真正在做的事是：集采降价后患者的年治疗费用变了多少？
一个新产品进医保后未来五年对医保基金的预算冲击有多大？在 DRG 付费下,
某类药品的成本结构是盈余还是亏损？本项目把这些做成可复现的计算流程。

## 数据来源与合规说明（重要）

国家医保局、NMPA 等站点部署了 JavaScript 反爬保护，普通 HTTP 客户端无法访问。

**本项目不抓取政府网站，也不尝试绕过任何反爬保护。** 工具围绕**用户自备的
结构化数据**设计：你从国家医保局或省级药采平台下载集采中选结果（PDF/Excel），
整理为文档化的表头后喂给工具。

`examples/` 中的样本数据**明确标注为示意性数据（ILLUSTRATIVE SAMPLE DATA）**，
不是真实药品价格，仅用于演示数据格式与计算流程。文件头、README、字段说明中均
有醒目标注。列名支持中文别名，便于直接使用中文表格。

## 快速开始

```bash
git clone https://github.com/leerogerstheman/ChinaHTA
cd ChinaHTA

# 用自备数据运行完整分析
python china_hta.py run --data 你的集采数据.csv --outdir 输出目录

# 用示例数据跑通全流程
python china_hta.py run --data examples/vbp_sample.csv --outdir examples/example_output
```

输出：SQLite + CSV + Excel（多工作表）+ Markdown 报告。

**环境要求**：Python 3.9+，依赖 numpy / pandas / openpyxl / XlsxWriter。

## 开发中修复的两个真实缺陷

**1. Beta 采样器静默失真（严重）**
`_beta_from_mean_sd` 先把均值裁剪到 (0,1) 再做矩匹配。当效应量均值 ≥1 时（累计 QALY，
如 1.08），它返回的分布均值是 0.91 / sd 0.285 —— 与目标完全不符。后果：PSA 的 ΔE 均值
是 **0.0080 而非 0.0800（差 10 倍）**，且 P(成本有效) 被错误报为 91.7% 而非 100%。
已修复：越界的 mean/sd 现在直接报错而非静默截断。

**2. 示例数据免责声明未进入报告（安全相关）**
`cmd_run` 硬编码 `is_sample=False`，导致 README 自己的示例命令生成的报告里**没有**
"示意性数据"提示 —— 存在把虚构价格读成真实数据的风险。已修复。

两个缺陷均有回归测试，并在 README §13 中记录。

## 验证方式（独立复算）

除单元测试外，用 `csv` + `fractions.Fraction` **精确有理数**写了一个**不 import `src/`
任何模块**的独立脚本复算（避免共享 bug 自我认证）：

- ICER：加权中选价 6.520763、参考价 29.032269 → ΔC=−8,216.699818、ΔE=0.08
  → **ICER=−102,708.747723**，与管线输出一致
- BIA：逐年展开 `dB*_y = T_y·s_y·(C_new−C_old)·d_y`（y1..y5），贴现后合计
  −1,328,878,287.81 vs 管线 −1,328,878,288 —— 全部吻合
- 一致性自检 10/10；删除全部输出后**从零重跑**，每一个 README 数字都精确复现

## 局限

- **CEA 的效应增量（ΔE=+0.08 QALY）是示意性假设**：集采改变的是价格而非疗效，
  若 ΔE=0 则 ICER 在构造上无定义。报告与 README 中均已标注，但这是分析上最弱的一环。
- **DRG 数据为合成构造**（5 个病组），权重与成本指数均为示意值。
- 年用量默认 365 单位/年（已标注）；真实分析需由用户提供 DDD 或说明书用法用量，
  工具刻意不自行推断 DDD。
- 样本数据为示意性数据，**不代表任何真实药品的实际价格**
- BIA/CEA 结果**高度依赖输入假设**（市场规模、爬坡曲线、贴现率、效用值），
  工具的作用是让假设显式化并可做敏感性分析，而非给出"正确答案"
- 输出**不构成医保决策或临床建议**
